<Callout type="info" title="Definisi singkat">
Database menyimpan data secara permanen. Di Next.js, akses database sebaiknya selalu dilakukan dari server, bukan dari Client Component.
</Callout>

Database digunakan agar data aplikasi bertahan secara permanen. Tanpa database, data hanya hidup di memory, file lokal, atau service sementara.

Di aplikasi Next.js, database biasanya diakses dari server, bukan dari browser.

## 🔐 Kenapa Harus dari Server?

Koneksi database membutuhkan credential seperti connection string, username, password, atau token. Credential seperti ini tidak boleh dikirim ke browser.

Server Component, Route Handler, dan Server Action berjalan di server. Karena itu, ketiganya bisa memanggil database client selama module database tidak diimpor ke Client Component.

## 📍 Tempat Database Dipakai

Database biasanya dipakai di:

- Server Component untuk membaca data awal.
- Server Action untuk mutation dari form.
- Route Handler untuk endpoint API, webhook, atau client eksternal.
- Data Access Layer untuk membungkus query dan aturan akses data.

## 📖 Alur Read

```text
User membuka halaman
Server Component berjalan
Data Access Layer membaca database
DTO dikembalikan ke halaman
HTML dan RSC payload dikirim ke client
```

## ✏️ Alur Mutation

```text
User submit form
Server Action berjalan
Input divalidasi
Data Access Layer menulis ke database
Cache atau route direvalidasi
User melihat data terbaru
```

## 🚫 Jangan Query dari Client Component

Client Component berjalan dengan asumsi browser. Jangan import database client di file `"use client"`.

Contoh yang harus dihindari:

```tsx
"use client";

import { db } from "@/lib/db";

export function UsersTable() {
  // Jangan query database dari Client Component.
  return null;
}
```

Lebih aman:

```tsx
import { getUsers } from "@/data/users";

export default async function UsersPage() {
  const users = await getUsers();

  return <UsersTable users={users} />;
}
```

## ✅ Ringkasan

Database harus diakses dari server. Gunakan Server Component untuk read, Server Action untuk mutation, dan Data Access Layer untuk menjaga query tetap rapi serta aman.
