<Callout type="info" title="Fokus utama bab ini">
Bab ini membahas authentication, session, authorization, protected route, login/register/logout, dan security check di Server Action serta Data Access Layer.
</Callout>

![Diagram alur authentication](/diagrams/auth-flow.svg)

Bab ini membahas identitas user dan pembatasan akses di aplikasi Next.js.

Authentication menjawab pertanyaan: siapa user ini? Setelah itu, session management menjaga status login antar request, dan authorization menentukan apa yang boleh dilakukan user tersebut.

Di App Router, auth biasanya melibatkan Server Actions untuk login/register/logout, cookie untuk session, Server Component untuk membaca session, dan Data Access Layer untuk membatasi akses data.

## 🎯 Hasil yang Diharapkan

Setelah bab ini selesai, kamu dapat membangun alur authentication dasar dan melindungi halaman tertentu dari user yang belum berhak mengaksesnya.

## 🧠 Mental Model

```text
User mengirim credentials
Server memvalidasi input
Server mengecek user
Session dibuat
Cookie dikirim ke browser
Request berikutnya membawa cookie
Server memverifikasi session
Authorization menentukan akses
```

## 🧪 Studi Kasus Bab Authentication

Bayangkan aplikasi memiliki tiga area:

```text
/login              -> halaman publik
/dashboard          -> hanya user login
/admin              -> hanya role admin
/tasks/[id]         -> hanya owner task
```

Dari sini terlihat bahwa login saja belum cukup. Server tetap harus mengecek session, role, permission, dan ownership data.

## 📝 Latihan Pemanasan

Jawab pertanyaan berikut:

1. Apa beda authentication dan authorization?
2. Kenapa cookie session harus `httpOnly`?
3. Kenapa pesan login sebaiknya umum seperti `Invalid credentials`?
4. Di mana sebaiknya ownership data dicek?
5. Kenapa menyembunyikan tombol admin di UI belum cukup aman?
