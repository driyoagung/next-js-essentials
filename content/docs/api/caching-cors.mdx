title: Caching dan CORS
description: Memahami caching GET Route Handler dan header CORS dasar.
---

<Callout type="info" title="Definisi singkat">
Caching mengatur apakah response boleh disimpan, sedangkan CORS mengatur apakah endpoint boleh diakses dari origin berbeda.
</Callout>

Route Handler punya perilaku caching yang perlu dipahami sejak awal.

Di Next.js versi modern, `GET` Route Handler tidak otomatis cached secara default. Jika response `GET` memang aman untuk disimpan, kamu perlu opt-in dengan route config.

## 📦 GET Tidak Cached Secara Default

Contoh endpoint dynamic:

```ts filename="app/api/time/route.ts"
export async function GET() {
  return Response.json({
    now: new Date().toISOString(),
  });
}
```

Endpoint seperti ini sebaiknya tetap dynamic karena hasilnya berubah setiap request.

## 🧊 Membuat GET Static

Jika data aman dianggap static, gunakan `dynamic = "force-static"`.

```ts filename="app/api/site-info/route.ts"
export const dynamic = "force-static";

export async function GET() {
  return Response.json({
    name: "Next.js Essential",
    version: "1.0.0",
  });
}
```

## 🔄 Revalidation

Untuk response yang boleh diperbarui berkala, gunakan `revalidate`.

```ts filename="app/api/posts/route.ts"
export const revalidate = 60;

export async function GET() {
  const response = await fetch("https://example.com/api/posts");
  const posts = await response.json();

  return Response.json(posts);
}
```

Nilai `60` berarti response dapat direvalidasi setelah 60 detik.

## 🧩 Dengan Cache Components

Jika fitur Cache Components aktif, `GET` Route Handler mengikuti model cache yang sama dengan route UI. Data yang uncached dapat dipindahkan ke helper dengan directive `"use cache"`.

```ts filename="app/api/products/route.ts"
import { cacheLife } from "next/cache";

export async function GET() {
  const products = await getProducts();

  return Response.json(products);
}

async function getProducts() {
  "use cache";
  cacheLife("hours");

  const response = await fetch("https://example.com/api/products");
  return response.json();
}
```

Directive `"use cache"` tidak diletakkan langsung di body Route Handler. Letakkan di helper function.

## 🌐 CORS Dasar

CORS diperlukan jika endpoint akan dipanggil dari origin berbeda.

```ts filename="app/api/public-data/route.ts"
export async function GET() {
  return Response.json(
    {
      message: "Public data",
    },
    {
      headers: {
        "Access-Control-Allow-Origin": "https://example.com",
        "Access-Control-Allow-Methods": "GET, POST, OPTIONS",
        "Access-Control-Allow-Headers": "Content-Type, Authorization",
      },
    },
  );
}
```

Untuk preflight request, kamu dapat membuat handler `OPTIONS`.

```ts filename="app/api/public-data/route.ts"
export async function OPTIONS() {
  return new Response(null, {
    status: 204,
    headers: {
      "Access-Control-Allow-Origin": "https://example.com",
      "Access-Control-Allow-Methods": "GET, POST, OPTIONS",
      "Access-Control-Allow-Headers": "Content-Type, Authorization",
    },
  });
}
```

## ✅ Ringkasan

`GET` Route Handler tidak cached secara default. Aktifkan caching hanya jika data aman disimpan. Tambahkan header CORS ketika endpoint perlu diakses dari origin lain.
