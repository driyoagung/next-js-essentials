Sebelum belajar fitur yang lebih kompleks, kamu perlu memahami satu hal penting: Next.js bukan sekadar cara lain untuk menulis React. Next.js adalah framework yang memberi aturan, struktur, dan fitur bawaan agar aplikasi React bisa berkembang menjadi aplikasi web production.

React membantu kita membuat antarmuka. Next.js membantu kita mengubah antarmuka itu menjadi aplikasi yang punya halaman, URL, layout, rendering, metadata, optimasi asset, dan sebagian kemampuan backend.

Banyak pemula langsung masuk ke coding tanpa memahami struktur. Akibatnya, saat project mulai berkembang, mereka bingung menjawab pertanyaan seperti:

Pertanyaan seperti itu akan sering muncul saat belajar Next.js. Karena itu, bab pertama ini sengaja berfokus pada pemahaman struktur, bukan hanya sintaks.

## 🧠 Mental Model Awal

Bayangkan kamu sedang membangun sebuah gedung.

React adalah bahan dan alat untuk membuat bagian-bagian gedung seperti pintu, jendela, meja, dan ruangan. Next.js adalah denah, aturan lantai, jalur masuk, sistem pencahayaan awal, dan cara gedung itu siap digunakan oleh pengunjung.

Dalam aplikasi web, gambaran sederhananya seperti ini:

```text
React
- Membuat komponen UI
- Mengelola interaksi
- Menyusun tampilan dari komponen kecil

Next.js
- Mengatur routing
- Mengatur layout
- Mengatur rendering
- Mengatur metadata
- Mengatur optimasi asset
- Mengatur build dan deployment
```

Jadi saat memakai Next.js, kamu tetap menulis React. Bedanya, React tersebut ditempatkan di dalam struktur aplikasi yang sudah punya convention.

## 💻 Contoh Sederhana

Di React biasa, sebuah komponen hanya menjadi fungsi yang menghasilkan UI:

```tsx
export function Welcome() {
  return <h1>Selamat datang</h1>;
}
```

Komponen di atas belum otomatis menjadi halaman yang bisa dibuka dari browser. Kamu masih perlu routing, konfigurasi, dan struktur aplikasi.

Di Next.js, file berikut langsung membuat halaman `/`:

```tsx filename="app/page.tsx"
export default function HomePage() {
  return <h1>Selamat datang</h1>;
}
```

Convention inilah yang membuat Next.js terasa berbeda. Nama file dan lokasi folder memiliki arti.

## 🧪 Studi Kasus Bab 1

Bayangkan kamu diminta membuat website sederhana untuk profil sekolah. Website tersebut punya halaman:

```text
/
/tentang
/program
/kontak
```

Dengan Next.js App Router, kamu dapat mulai berpikir dari URL terlebih dahulu. Jika URL yang dibutuhkan adalah `/tentang`, maka struktur foldernya mengarah ke:

```text
app/
+-- tentang/
    +-- page.tsx
```

Jika semua halaman harus punya navbar dan footer yang sama, maka kamu tidak perlu menulis navbar di setiap halaman. Kamu bisa menaruhnya di `layout.tsx`.

Dari studi kasus sederhana ini, kamu mulai melihat pola penting Next.js:

1. URL dibentuk dari folder
2. Halaman dibuat dengan `page.tsx`
3. Tampilan bersama dibuat dengan `layout.tsx`
4. File pendukung disimpan di luar struktur route jika tidak ingin menjadi URL
