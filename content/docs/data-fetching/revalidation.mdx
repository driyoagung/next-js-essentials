<Callout type="info" title="Definisi singkat">
Revalidation adalah proses memperbarui cache agar aplikasi tetap cepat tanpa membiarkan data lama dipakai selamanya.
</Callout>

Revalidation adalah proses memperbarui data yang sudah disimpan di cache. Dengan revalidation, aplikasi tetap bisa cepat karena memakai cache, tetapi data tidak dibiarkan basi selamanya.

## ⏱️ Time-based Revalidation

Time-based revalidation memperbarui cache setelah durasi tertentu.

```ts
async function getProducts() {
  const response = await fetch("https://example.com/api/products", {
    next: {
      revalidate: 60,
    },
  });

  return response.json();
}
```

Contoh di atas membuat data dapat diperbarui setelah 60 detik.

## 🧩 Revalidation dengan Cache Life

Jika memakai Cache Components, kamu dapat menentukan umur cache dengan `cacheLife`.

```ts filename="app/lib/products.ts"
import { cacheLife } from "next/cache";

export async function getProducts() {
  "use cache";
  cacheLife("hours");

  const response = await fetch("https://example.com/api/products");
  return response.json();
}
```

Profile seperti `"hours"` cocok untuk data yang tidak sering berubah.

## 🏷️ Tag-based Revalidation

Cache bisa diberi tag, lalu tag tersebut di-invalidate setelah ada perubahan data.

```ts filename="app/lib/products.ts"
import { cacheTag } from "next/cache";

export async function getProducts() {
  "use cache";
  cacheTag("products");

  const response = await fetch("https://example.com/api/products");
  return response.json();
}
```

Setelah mutation, cache dapat diperbarui.

```ts filename="app/products/actions.ts"
"use server";

import { revalidateTag } from "next/cache";

export async function createProduct(formData: FormData) {
  const name = formData.get("name");

  await fetch("https://example.com/api/products", {
    method: "POST",
    body: JSON.stringify({ name }),
  });

  revalidateTag("products", "max");
}
```

## 🛣️ Path-based Revalidation

Jika ingin memperbarui cache berdasarkan path, gunakan `revalidatePath`.

```ts filename="app/products/actions.ts"
"use server";

import { revalidatePath } from "next/cache";

export async function updateProduct() {
  await saveProduct();
  revalidatePath("/products");
}
```

## 🧭 Kapan Memakai Masing-masing?

| Kebutuhan | Strategi |
| --- | --- |
| Data boleh refresh berkala | `next.revalidate` atau `cacheLife` |
| Data berubah setelah mutation | `revalidateTag` atau `updateTag` |
| Invalidate satu halaman tertentu | `revalidatePath` |
| User harus langsung melihat data baru | `updateTag` atau redirect setelah mutation |

## 🧪 Studi Kasus: Setelah Create Product

Saat user membuat produk baru, halaman `/products` harus menampilkan data terbaru.

Flow yang umum:

```text
Submit form
Server Action menyimpan produk
revalidatePath('/products')
redirect('/products')
```

Jika data produk diberi tag `products`, kamu juga bisa memakai tag-based revalidation agar semua data yang terkait produk ikut disegarkan.

<Callout type="idea" title="Pilih berdasarkan dampak mutation">
Jika mutation hanya memengaruhi satu halaman, `revalidatePath` cukup. Jika mutation memengaruhi banyak tempat yang memakai data sama, pertimbangkan tag-based revalidation.
</Callout>

## 📝 Latihan

Pilih strategi revalidation untuk kasus berikut:

1. Artikel baru dibuat dan list blog harus update.
2. Profile user diubah dan halaman profile harus refresh.
3. Produk berubah dan muncul di homepage, list, dan detail.
4. Data statistik admin harus refresh setiap 60 detik.

## ✅ Ringkasan

Revalidation menjaga cache tetap berguna tanpa mengorbankan freshness terlalu jauh. Pilih strategi berdasarkan kapan data berubah dan seberapa cepat user harus melihat perubahan itu.
