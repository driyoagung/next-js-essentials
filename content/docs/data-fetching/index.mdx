</Callout>

![Diagram alur data fetching](/diagrams/data-fetching-flow.svg)

Bab ini menggabungkan data fetching dengan state UI yang muncul saat data sedang dimuat, gagal dimuat, atau tidak ditemukan.

Di App Router, data biasanya diambil dari Server Component. Pendekatan ini membuat halaman bisa membaca data di server, mengurangi kebutuhan API internal yang tidak perlu, dan menjaga secret tetap tidak dikirim ke browser.

Namun data fetching tidak berdiri sendiri. Setelah mengambil data, kamu perlu memikirkan apakah data perlu cache, kapan data harus diperbarui, bagaimana UI saat loading, apa yang terjadi ketika request gagal, dan bagaimana menampilkan halaman not found.

## 🎯 Hasil yang Diharapkan

Setelah bab ini selesai, kamu dapat mengambil data di halaman Next.js dan menyediakan pengalaman loading, error, serta not found yang jelas.

## 🧠 Mental Model

```text
Data dibutuhkan
Fetch di server
Tentukan cache atau dynamic
Sediakan loading state
Tangani error dan not found
Render UI
```

## 🧪 Studi Kasus Bab Ini

Bayangkan kamu membuat halaman katalog produk. Halaman tersebut membutuhkan:

- Daftar produk dari API atau database.
- Filter berdasarkan query string.
- Cache untuk kategori yang jarang berubah.
- Data fresh untuk stok produk.
- Loading skeleton saat data lambat.
- Error UI jika API gagal.
- Not found jika detail produk tidak ada.

Alur berpikirnya bukan hanya "ambil data", tetapi juga "apa pengalaman user saat data belum siap atau gagal?".

## 📝 Latihan Pemanasan

Rancang strategi data untuk halaman `/products`:

1. Data apa yang boleh di-cache?
2. Data apa yang harus selalu fresh?
3. Bagian mana yang butuh loading UI?
4. Kapan memakai `notFound()`?
5. Error apa yang perlu ditampilkan sebagai pesan biasa?
