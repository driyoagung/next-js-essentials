<Callout type="info" title="Definisi singkat">
`notFound()` digunakan saat data memang tidak ditemukan, bukan saat sistem gagal. Ini membantu user dan mesin pencari memahami bahwa resource tidak ada.
</Callout>

Tidak semua kegagalan data adalah error sistem. Jika data memang tidak ada, gunakan `notFound()` agar user mendapatkan UI 404 yang tepat.

## 💻 Contoh Detail Page

```tsx filename="app/posts/[id]/page.tsx"
import { notFound } from "next/navigation";

type Post = {
  id: number;
  title: string;
  body: string;
};

async function getPost(id: string): Promise<Post | null> {
  const response = await fetch(
    `https://jsonplaceholder.typicode.com/posts/${id}`,
  );

  if (response.status === 404) {
    return null;
  }

  if (!response.ok) {
    throw new Error("Failed to fetch post");
  }

  return response.json();
}

export default async function PostDetailPage({
  params,
}: {
  params: Promise<{ id: string }>;
}) {
  const { id } = await params;
  const post = await getPost(id);

  if (!post) {
    notFound();
  }

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  );
}
```

## 🧭 File not-found.tsx

Buat file `not-found.tsx` pada segment yang ingin punya UI 404 khusus.

```tsx filename="app/posts/[id]/not-found.tsx"
import Link from "next/link";

export default function NotFound() {
  return (
    <main>
      <h1>Post not found</h1>
      <p>The post you are looking for does not exist.</p>
      <Link href="/posts">Back to posts</Link>
    </main>
  );
}
```

Jika `notFound()` dipanggil di `app/posts/[id]/page.tsx`, maka Next.js akan menampilkan `not-found.tsx` terdekat.

## ⚖️ Not Found vs Error

| Kondisi | Gunakan |
| --- | --- |
| Data tidak ada | `notFound()` |
| Request gagal karena server/API bermasalah | `throw new Error()` |
| Validasi input gagal | Return value atau pesan validasi |

## 🧪 Studi Kasus: Detail Produk Tidak Ada

User membuka:

```text
/products/999
```

Jika produk dengan ID tersebut tidak ada, tampilkan `not-found.tsx`, bukan error 500. Ini memberi pesan yang lebih tepat: sistem tidak rusak, resource memang tidak ditemukan.

Flow:

```text
Baca params id
Query produk
Jika null -> notFound()
Jika ada -> render detail
```

## 📝 Latihan

Tentukan apakah kasus berikut memakai `notFound()`, error UI, atau empty state:

1. Produk dengan ID tertentu tidak ada.
2. Database tidak bisa dihubungi.
3. Search produk tidak menghasilkan data.
4. Artikel dengan slug salah.
5. User tidak punya akses ke halaman admin.

## ✅ Ringkasan

Gunakan `notFound()` untuk kasus data tidak ditemukan. Jangan mencampurnya dengan error sistem, karena keduanya memberi makna berbeda pada user dan mesin pencari.
