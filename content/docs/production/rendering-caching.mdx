<Callout type="info" title="Pilih dengan sadar">
Strategi rendering dan caching harus mengikuti karakter data: publik atau personal, stabil atau sering berubah, murah atau mahal diambil.
</Callout>

Next.js dapat merender halaman secara static atau dynamic. Pilihan ini dipengaruhi oleh data, request-time API, dan strategi cache.

## 🧊 Static Rendering

Static rendering cocok untuk halaman yang sama untuk semua user.

Contoh:

- Landing page.
- Dokumentasi publik.
- Blog post yang jarang berubah.

Data yang stabil bisa di-cache agar request lebih cepat.

## ⚡ Dynamic Rendering

Dynamic rendering dibutuhkan ketika hasil halaman bergantung pada request user.

Contoh:

- Membaca `cookies()`.
- Membaca `headers()`.
- Menggunakan `searchParams`.
- Menampilkan dashboard personal.

Request-time API membuat route perlu dirender sesuai request.

## 🌊 Streaming

Jika ada bagian lambat, gunakan `loading.tsx` atau `Suspense`.

```tsx
import { Suspense } from "react";

export default function DashboardPage() {
  return (
    <main>
      <h1>Dashboard</h1>
      <Suspense fallback={<p>Loading chart...</p>}>
        <Chart />
      </Suspense>
    </main>
  );
}
```

Streaming membantu UI awal muncul lebih cepat.

## 📦 Cache dengan Niat

Cache cocok untuk data stabil. Hindari cache untuk data personal atau data yang harus selalu fresh.

```ts
const response = await fetch("https://example.com/api/posts", {
  next: {
    revalidate: 60,
  },
});
```

Jika memakai Cache Components, gunakan `"use cache"` dan `cacheLife()` sesuai kebutuhan.

## 🔄 Revalidation Setelah Mutation

Setelah Server Action mengubah data, panggil revalidation.

```ts
import { revalidatePath } from "next/cache";

revalidatePath("/employees");
```

## ✅ Ringkasan

Gunakan static rendering untuk data publik yang stabil, dynamic rendering untuk data request-specific, streaming untuk bagian lambat, dan cache hanya ketika data aman disimpan.
